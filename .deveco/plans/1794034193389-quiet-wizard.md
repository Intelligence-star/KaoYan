# 配置签名并验证项目可运行

## Goal
为当前 HarmonyOS 项目（`com.example.kaoyan`，考研通）配置自动签名，解决 `build-profile.json5` 中 `signingConfigs` 为空的问题，并在本地模拟器上完成构建、部署、启动，验证项目可运行。

## Scope / Non-goals
**Scope**
- 完成签名配置（自动生成调试签名材料并写回 `build-profile.json5`）
- 在本地模拟器上跑通「构建 → 部署 → 启动」全链路
- 验证首屏 `pages/Index`（Hello World 页）正常显示

**Non-goals**
- 不修改任何业务/页面代码
- 不生成发布（release）签名与上架物料
- 不处理首屏功能开发

## Current State And Constraints
- 项目结构完整：入口链 `module.json5 → EntryAbility.ets → pages/Index.ets` 无断链，所有资源引用均存在，源文件无 ArkTS 违规。
- 当前障碍：
  1. `build-profile.json5` 中 `"signingConfigs": []` 为空，但 product 引用了 `"signingConfig": "default"`，未签名无法部署。
  2. `local.properties` 为空（无 SDK 路径），但 devecocli 走 DevEco Studio 工具链定位 SDK，不依赖该文件。
- 环境依赖：devecocli 需能发现 DevEco Studio（或 Command Line Tools，需设置 `DEVECO_CLI_CLT_PATH`）。
- 签名生成与模拟器运行均需可用的本地模拟器实例。

## Design

采用 devecocli 官方首次签名流程，并结合「模拟器」运行目标，执行顺序调整如下（签名生成需要连接设备/模拟器用于设备注册，故模拟器先就绪）：

```
devecocli auth login
  → devecocli emulator list / create / image download / start
  → devecocli signature generate --product default
  → devecocli check arkts
  → devecocli build
  → devecocli run
  → devecocli ui screenshot（验证）
```

关键决策：
- **签名**：用 `devecocli signature generate` 自动生成 `.p12`/`.cer`/`.p7b` 调试材料，并自动把 `signingConfigs` + `products` 写回 `build-profile.json5`（密码以 AES-128-GCM 加密存储）。无需手工编辑。
- **运行目标**：本地模拟器（用户已确认）。若无已创建实例/镜像，需先创建并下载镜像（下载耗时约 30+ 分钟）。
- **验证**：`devecocli check arkts` 做编译前静态检查；`devecocli build` 编译；`devecocli run` 部署启动；最后 `devecocli ui screenshot` 截图确认首屏。

## Key Files
- [build-profile.json5](build-profile.json5) — 签名配置写入目标（signingConfigs 会被自动填充）
- [entry/src/main/module.json5](entry/src/main/module.json5) — 入口声明（只读，不改动）
- [entry/src/main/ets/entryability/EntryAbility.ets](entry/src/main/ets/entryability/EntryAbility.ets) — 入口 Ability（只读，不改动）
- [entry/src/main/ets/pages/Index.ets](entry/src/main/ets/pages/Index.ets) — 首屏页面（只读，不改动）

## Execution Sequence

> 以下命令均在项目根目录 `F:\KaoYan` 执行。标 `[Outside sandbox]` 的命令需在沙箱外执行。

### 1. 登录华为开发者账号
- 执行：`devecocli auth login`（打开浏览器 OAuth，需用户手动完成登录）
- 校验：`devecocli auth status` 显示已登录用户。
- 注意：此步为交互式，必须用户配合；签名生成依赖该登录态。

### 2. 准备并启动本地模拟器
- 检查现有实例：`devecocli emulator list`
- 若已有实例：`devecocli emulator start <name>` 启动（等待启动完成）。
- 若无实例：
  - 检查已下载镜像：`devecocli emulator image list`
  - 无镜像则下载：`devecocli emulator image download --device-type phone --os-version <版本>`（30+ 分钟，需长超时；不可自动重试）
  - 创建实例：`devecocli emulator create <name> --device-type phone --os-version <版本>`
  - 启动：`devecocli emulator start <name>`
- 确认就绪：`devecocli device list` 能看到该模拟器。
- 注意：签名生成前必须有运行中的模拟器（设备注册）。

### 3. 自动生成签名
- 执行：`devecocli signature generate --product default`
- 结果：`~/.ohos/config/` 下生成签名材料；`build-profile.json5` 自动写入 `signingConfigs` + `products`。
- 校验：读取 `build-profile.json5`，确认 `signingConfigs` 非空且含 `default` 条目。

### 4. ArkTS 静态检查
- 执行：`devecocli check arkts`
- 若报错按提示修复（预期无错误）。

### 5. 编译构建
- 执行：`devecocli build`
- 校验：构建成功，生成 `entry/build/...` 产物。

### 6. 部署到模拟器并启动
- 执行：`devecocli run`
- 若多个目标设备出现 `DEVICE_SELECTION_REQUIRED`，选择模拟器后重试：`devecocli run --device "<模拟器名/序列号>"`。
- 若报 `error:install sign info inconsistent`：`devecocli run --uninstall` 后重试。

### 7. 验证运行结果
- 截图：`devecocli ui screenshot --path ./screenshots/home.png`
- 日志（可选）：`devecocli log --bundle-name com.example.kaoyan --tail 200`
- 预期：截图中显示「Hello World」文本页面（点击后变「Welcome」）。

## Verification
| 检查项 | 命令 / 方法 | 通过标准 |
|---|---|---|
| 登录态 | `devecocli auth status` | 显示已登录用户 |
| 模拟器就绪 | `devecocli device list` | 列表含目标模拟器 |
| 签名已写入 | 读 `build-profile.json5` | `signingConfigs` 含 `default` 且非空 |
| ArkTS 静态检查 | `devecocli check arkts` | 无错误输出 |
| 编译 | `devecocli build` | 构建成功退出码 0 |
| 部署启动 | `devecocli run` | 无报错，应用启动 |
| UI 验证 | `devecocli ui screenshot` | 截图显示首屏 Hello World |

## Risks And Compatibility
- **登录交互**：`auth login` 需用户浏览器手动完成 OAuth，无法全自动。
- **镜像下载耗时**：首次无镜像需 30+ 分钟；下载失败不可自动重试，需手动执行。
- **签名配额**：若报 `205389872`（证书上限）/`205389938`（provision 上限），需在 DevEco Studio 或 AGC 清理旧测试证书后重试。
- **设备注册**：`signature generate` 需要运行中的模拟器；若缺设备会失败，先确保模拟器启动。
- **SDK 定位**：若 devecocli 找不到 DevEco Studio，需设置 `DEVECO_CLI_CLT_PATH` 指向 Command Line Tools。
- **`build-profile.json5` 被签名流程改写**：属预期变更，非破坏。

## Rollback
- 代码层面本次无改动，无需回滚。
- 若签名配置异常：删除 `build-profile.json5` 中新增的 `signingConfigs` 条目（恢复为 `"signingConfigs": []`），并删除 `~/.ohos/config/` 下本次生成的 `.p12/.csr/.cer/.p7b` 即可回到初始状态。
- 若模拟器镜像/实例异常：`devecocli emulator delete <name>` 删除实例。
